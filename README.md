# بک‌اند پلتفرم برنامه‌ریزی مطالعاتی کنکور

فاز ۰: پی‌ریزی پروژه + مدل دیتابیس + اتصال.

## پیش‌نیازها

- Node.js نسخه ۱۸ به بالا
- MySQL نسخه ۸ به بالا نصب‌شده (لوکال یا یک سرویس ابری مثل PlanetScale/Railway/Aiven)

## مراحل راه‌اندازی

1. نصب پکیج‌ها:
   ```bash
   npm install
   ```

2. کپی فایل تنظیمات و پر کردن مقادیر واقعی:
   ```bash
   cp .env.example .env
   ```
   سپس مقدار `DATABASE_URL` را با اطلاعات دیتابیس واقعی خودت جایگزین کن.

3. ساخت جدول‌ها در دیتابیس بر اساس مدل تعریف‌شده:
   ```bash
   npx prisma migrate dev --name init
   ```
   این دستور هم جدول‌ها را می‌سازد و هم Prisma Client را تولید می‌کند.

4. ساخت تگ‌های پیش‌فرض (پیشروی، تمرین، مرور، آمادگی امتحان):
   ```bash
   node prisma/seed.js
   ```

5. اجرای سرور در حالت توسعه (با ری‌استارت خودکار روی تغییر فایل):
   ```bash
   npm run dev
   ```

6. تست سلامت سرور:
   مرورگر یا Postman را باز کن و به آدرس زیر برو:
   ```
   http://localhost:4000/health
   ```
   اگر پاسخ `{"status":"ok",...}` را دیدی، فاز ۰ با موفقیت انجام شده.

## ساختار پوشه‌ها

```
prisma/
  schema.prisma     مدل دیتابیس
  seed.js            اسکریپت ساخت تگ‌های پیش‌فرض
  repair-orphans.js  تعمیر دیتابیس: پاک‌سازی ردیف‌های یتیم + ساخت قیدهای خارجی جاافتاده
src/
  app.js             تعریف اپ Express و middleware ها
  server.js           فایل اجرایی که سرور را بالا می‌آورد
  config/prisma.js    اتصال singleton به دیتابیس
  routes/            (فاز بعد) مسیرهای API
  controllers/       (فاز بعد) منطق هر route
  middleware/        (فاز بعد) مثل auth middleware
```

## تعمیر دیتابیس: ردیف‌های یتیم و قیدهای خارجی

اگر بعد از حذف یک دانش‌آموز (یا مشاور) با خطای زیر روبه‌رو شدید و پنل
سوپرادمین بالا نیامد، یعنی در دیتابیس قید خارجی (FOREIGN KEY) مربوطه ساخته
نشده یا قانونش اشتباه است و ردیف لینک به کاربرِ حذف‌شده باقی مانده:

```
Inconsistent query result: Field student is required to return data, got `null` instead
```

```bash
npm run db:repair   # یا: node prisma/repair-orphans.js
```

این اسکریپت (idempotent است، چند بار اجرا شدن مشکلی ندارد):

1. ردیف‌های یتیم همه‌ی جدول‌ها را پاک می‌کند.
2. قیدهای خارجی تعریف‌شده در `schema.prisma` را در صورت نبود (یا با قانون
   `ON DELETE` اشتباه) می‌سازد تا این مشکل تکرار نشود.

قبل از اجرا از دیتابیس بکاپ بگیرید. سرور هم موقع بالا آمدن یک‌بار همین
پاک‌سازی را خودش انجام می‌دهد، ولی ساخت قیدهای خارجی فقط با اسکریپت بالاست.
